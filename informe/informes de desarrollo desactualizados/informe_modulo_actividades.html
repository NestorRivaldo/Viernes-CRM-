Informe Final Módulo 5: Actividades y Seguimiento

Documentación técnica y funcional del motor de transacciones diarias del CRM.

ESTADO: LISTO (V1)

1. Propósito y Alcance

El módulo permite registrar, editar y controlar las acciones que realizan los vendedores durante la gestión de clientes, leads y oportunidades. Actúa como el puente principal para el seguimiento comercial.

Responde a las preguntas: ¿Qué se hizo, quién lo hizo, con quién, sobre qué oportunidad, está vencida y cuál es su estado?

2. Correcciones Implementadas (Cierre de Módulo)

  • Edición Completa: Se habilitó el método `actualizar` mediante `PUT /api/v1/actividades/{id}`, permitiendo la modificación integral de la actividad.
  • idUsuario Unificado: Tras analizar `Clientes`, `Leads` y `Oportunidades`, se mantuvo y validó el uso de `String responsable` para evitar rupturas arquitectónicas. El campo final es `idUsuario (String)`.
  • Validación de Relaciones Cruzadas: Se implementó `RelacionValidationPort` aislando las dependencias. Antes de guardar/editar se valida que el `idCliente`, `idLead` e `idOportunidad` existan en DB (vía `SpringDataRepository`).
  • Actividades Vencidas: Se añadió lógica derivada `(PENDIENTE + fecha pasada)`. No es un estado en base de datos. Se refleja en el API mediante `?vencidas=true` y un flag booleano `vencida` en el Response.
  • Testing Completo: Se implementó `ActividadControllerTest` (Mockito + WebMvcTest/StandaloneSetup) y `ActividadServiceTest`, validando exitosamente flujos válidos y excepciones de negocio.

3. Endpoints de la API Final

Todos los endpoints respetan el diseño REST y las reglas de validación hexagonal:

POST   /api/v1/actividades              # Registrar nueva actividad (Valida relaciones)
GET    /api/v1/actividades              # Listar (Filtros: ?estado=, ?idCliente=, ?vencidas=true)
GET    /api/v1/actividades/{id}         # Obtener detalle (Muestra flag vencida)
PUT    /api/v1/actividades/{id}         # Edición completa (Valida existencias)
PATCH  /api/v1/actividades/{id}/estado  # Cambio rápido de estado (Ej. Completada)
DELETE /api/v1/actividades/{id}         # Eliminar registro

4. Arquitectura y Persistencia

Se consolidó la persistencia oficial utilizando Oracle XE. La tabla principal sigue siendo CRM_ACTIVIDADES y mapea correctamente llaves foráneas lógicas.

com.viernes.actividades/
├── domain/                      # Actividad, TipoActividad, EstadoActividad
├── application/
│   ├── dto/                 # ActividadRequest, ActividadResponse (+ vencida)
│   ├── port/in/             # ManageActividadUseCase
│   ├── port/out/            # ActividadPersistencePort, RelacionValidationPort
│   └── service/             # ActividadService (Orquestador y Validador)
└── adapters/
    ├── in/web/              # ActividadController
    └── out/persistence/     # Adapters (Validaciones + Persistencia en Oracle)

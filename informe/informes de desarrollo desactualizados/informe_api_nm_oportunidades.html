1. Resumen

La Wave 2 (relaciones N:M de oportunidades con contactos, productos y colaboradores) quedó cortada a mitad: toda la lógica existía (dominio, puertos, adapters, servicio con 10 métodos, tablas en Oracle) pero no había forma de invocarla porque el controller no exponía los endpoints. En esta sesión se agregaron los 10 endpoints REST y se verificó el flujo completo contra Oracle y Keycloak reales. El backend N:M queda 100% operativo vía API.

2. Punto de partida (diagnóstico previo)

  • Los "~400 errores" reportados no existían en el código: eran artefactos corruptos que el language server del IDE (Antigravity, extensión redhat.java sobre JRE 25) escribía en target/classes, la misma carpeta que usa Maven.
  • Estado de la Wave 2 al iniciar la sesión: servicio completo pero sin endpoints; frontend sin UI de detalle; tablas junction creadas pero vacías; todo el trabajo sin commitear.
  • Un bug real ya estaba corregido en el working tree: el choque de nombre del bean contactoQueryAdapter entre los módulos actividades y oportunidades (resuelto con @Component("oportunidadContactoQueryAdapter")).

5. Incidente durante la sesión (misma causa raíz de los "400 errores")

El problema del IDE volvió a ocurrir en vivo. Al guardar la edición del controller, el language server compiló el archivo con su ECJ y escribió una clase rota en target/classes (java.lang.Error: Unresolved compilation problem — 'Flexible Constructor Bodies' is only available with source level 25). El primer mvn test falló por ese artefacto, no por el código fuente. Se resolvió con ./mvnw clean test (full rebuild con javac).

Recomendación permanente: ejecutar en el IDE "Java: Clean Java Language Server Workspace", o desactivar su auto-build para este proyecto; y usar siempre ./mvnw clean antes de test/run mientras conviva con el IDE.

03 De qué módulos copiar

Tu idea de reutilizar código es correcta. Esto es lo que cada módulo te aporta para el examen.

Resumen de reutilización: tu idea de reutilizar es correcta y de hecho ya se hizo. El módulo clinica actual es una adaptación simplificada de etiquetas (para clínicas) + productos (para el enum de estado) + el patrón @ManyToMany de JPA (para la relación N:M, más simple que el de actividades).

07 El patrón N:M explicado

La relación muchos-a-muchos entre consultorios y especialidades es lo que más puntos vale. Así funciona en tu código.

Cómo lo resuelve tu código

Tu ConsultorioEntity usa @ManyToMany con @JoinTable. JPA crea y maneja la tabla intermedia CONSULTORIO_ESPECIALIDAD automáticamente:

@ManyToMany(fetch = FetchType.EAGER) @JoinTable( name = "CONSULTORIO_ESPECIALIDAD", schema = "EXA_CLINICA", joinColumns = @JoinColumn(name = "ID_CONSULTORIO"), inverseJoinColumns = @JoinColumn(name = "ID_ESPECIALIDAD") ) private Set<EspecialidadEntity> especialidades = new HashSet<>();

Y tu ConsultorioService.crearConsultorio() ya hace lo correcto:

// 1. Busca la clínica por ID ClinicaEntity clinica = clinicaRepository.findById(request.idClinica())...; // 2. Busca las especialidades por los IDs que mandó el frontend Set<EspecialidadEntity> especialidades = new HashSet<>(); if (request.especialidadIds() != null && !request.especialidadIds().isEmpty()) { especialidades.addAll(especialidadRepository.findAllById(request.especialidadIds())); } // 3. Crea el consultorio con las especialidades asignadas ConsultorioEntity entity = ConsultorioEntity.builder() .clinica(clinica) .codigo(request.codigo()) .tarifaHora(request.tarifaHora()) .estado(request.estado()) .especialidades(especialidades) .build(); // 4. Guarda — JPA inserta en CONSULTORIOS y en CONSULTORIO_ESPECIALIDAD return toResponse(consultorioRepository.save(entity));
El código ya está bien. JPA se encarga de la tabla intermedia. Solo necesitas que la BD exista y que el backend conecte. Lo que debes verificar es que FetchType.EAGER esté activo (sí lo está) para que al consultar el consultorio traiga las especialidades de una vez.

08 La base de datos: qué ejecutar

El examen trae 3 scripts para PowerShell. El único cambio que necesitas es el usuario de los GRANT.

ScriptQué haceTu cambio
Script 1: EsquemaCREATE USER EXA_CLINICA IDENTIFIED BY "123456" + permisosNinguno. Funciona igual.
Script 2: Tablas + semillas + permisosCrea 4 tablas, inserta datos, hace GRANT ... TO BOMERP_APPCambia BOMERP_APP por BOM_VENTAS en las 4 líneas de GRANT
Script 3: VerificarSELECT table_name FROM dba_tables WHERE owner='EXA_CLINICA'Ninguno. Debe listar 4 tablas.
Esto es lo que más puede fallar. Si tu backend usa BOM_VENTAS y el script le da permisos a BOMERP_APP, el backend no puede leer EXA_CLINICA.CLINICAS y todo falla con "tabla no existe" o "permiso insuficiente". Solución: cambia las 4 líneas de GRANT a TO BOM_VENTAS, o ejecuta los GRANT manualmente después del script 2.

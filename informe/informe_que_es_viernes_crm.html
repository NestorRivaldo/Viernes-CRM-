Definición y propósito del sistema

🏢 ¿Qué es Viernes CRM V1?

Viernes CRM V1 es un sistema de Gestión de Relaciones con Clientes (Customer Relationship Management) diseñado para equipos comerciales y de ventas. Permite gestionar de forma integral todo el ciclo de vida comercial: desde la captación de leads hasta el cierre de oportunidades, la generación de propuestas/cotizaciones y el seguimiento de actividades.

El sistema fue desarrollado como proyecto final integrador de la asignatura Lenguaje de Programación II (LP2), bajo el marco del proyecto BomERP, que busca construir módulos ERP funcionales con tecnologías empresariales reales.

💡
CRM = Customer Relationship Management. Es un software que centraliza toda la información de clientes, contactos, oportunidades de venta y actividades comerciales en un solo lugar, facilitando la toma de decisiones y el seguimiento del equipo de ventas.
2

El problema que resuelve

❌ Sin un CRM, las empresas enfrentan:

  • Información de clientes dispersa en hojas de Excel, correos y notas
  • No hay visibilidad del avance del equipo de ventas
  • Se pierden oportunidades por falta de seguimiento
  • No se puede medir el rendimiento del equipo comercial
  • Los leads captados de campañas de marketing no se gestionan
  • Las propuestas/cotizaciones se hacen manualmente sin trazabilidad

✅ Con Viernes CRM V1, la empresa puede:

  • Centralizar clientes, contactos y leads en una sola plataforma
  • Seguir el pipeline de ventas con oportunidades en etapas visuales
  • Generar propuestas/cotizaciones con productos del catálogo
  • Programar y dar seguimiento a llamadas, reuniones y tareas
  • Ver un dashboard con métricas de ventas en tiempo real
  • Gestionar campañas de marketing y sus leads asociados
  • Controlar permisos por rol (ADMIN, JEFE, VENDEDOR)
  • Comunicarse internamente a través de la mensajería del sistema

Módulos funcionales del sistema

Viernes CRM V1 está compuesto por 12 módulos funcionales organizados en una arquitectura modular (Spring Modulith). Cada módulo es independiente y se comunica con otros mediante referencias lógicas de ID.

👥

Clientes

Gestión de empresas clientes con datos fiscales, dirección, industria y contactos asociados (1:N).

📇

Contactos

Personas clave dentro de cada cliente: nombre, cargo, email, teléfono. Vinculados a actividades y oportunidades.

🎯

Leads

Prospectos de venta con información de fuente de captación, estado (nuevo, contactado, calificado) y datos de empresa.

💰

Oportunidades

Pipeline de ventas con etapas (Prospección → Calificación → Propuesta → Negociación → Cerrada). Incluye relaciones N:M con contactos, productos y colaboradores.

📋

Propuestas / Cotizaciones

Documentos comerciales con detalles de productos, cantidades, precios y estados (borrador, enviada, aprobada, rechazada, cancelada).

📅

Actividades

Llamadas, reuniones, tareas y seguimientos. Con participantes (N:M contactos) y etiquetas (N:M etiquetas).

📊

Dashboard

Métricas en tiempo real: conteo de clientes, leads, oportunidades, valor total del pipeline. Datos reales de Oracle, sin mocks.

📦

Productos

Catálogo de productos/servicios con nombre, precio, categoría y descripción. Asociables a oportunidades y propuestas.

👫

Equipos

Grupos de vendedores con nombre, líder y miembros (N:M con usuarios). Permiten organizar el equipo comercial.

📣

Marketing / Campañas

Campañas de marketing con presupuesto, fechas y leads asociados (N:M). Permiten rastrear la fuente de cada prospecto.

🏷️

Etiquetas

Sistema de clasificación por tags con color configurable. Asociables a actividades para categorización flexible (N:M).

💬

Mensajería

Sala de chat general para comunicación interna del equipo. Mensajes en tiempo real con polling cada 5 segundos y badge de no leídos.

Roles de usuario y permisos

El sistema implementa control de acceso basado en roles (RBAC) mediante Keycloak OIDC. Cada usuario tiene asignado un rol que determina qué operaciones puede realizar.

🛡️

ADMIN Administrador

Acceso total al sistema. Puede crear, editar y eliminar cualquier registro. Gestiona usuarios. Puede aprobar, rechazar y cancelar propuestas. Administra catálogos (productos, equipos, etiquetas, campañas, fuentes).

👔

JEFE Jefe de Ventas

Puede crear y editar registros. Puede aprobar, rechazar y cancelar propuestas. Puede gestionar catálogos. No puede eliminar registros de negocio (clientes, leads, oportunidades, propuestas, actividades). No puede gestionar usuarios.

🧑‍💼

VENDEDOR Vendedor

Puede crear y editar clientes, leads, oportunidades, propuestas y actividades. No puede eliminar registros. No puede aprobar/rechazar propuestas. No puede modificar catálogos ni gestionar usuarios. Si intenta una acción prohibida, recibe un error 403 Forbidden.

Arquitectura del sistema

🏛️ Arquitectura Hexagonal (Ports & Adapters)

El backend de Viernes CRM utiliza Arquitectura Hexagonal, donde cada módulo se organiza en tres capas independientes que separan la lógica de negocio de la infraestructura.

com.viernes.{modulo}/ ├── adapters/ │ ├── in/web/ → Controllers REST (@RestController) │ └── out/persistence/ → Entities JPA, Repositories, Adapters ├── application/ │ ├── dto/ → Request/Response DTOs │ ├── port/in/ → Use Case interfaces (puertos de entrada) │ ├── port/out/ → Persistence Port interfaces (puertos de salida) │ └── service/ → Implementación de los Use Cases └── domain/ → Entidades de dominio, enums, value objects

🔄 Flujo de una petición HTTP

1. El usuario hace una acción en el frontend Angular → 2. Angular envía una petición HTTP con token JWT → 3. Spring Security valida el token con Keycloak → 4. El Controller recibe la petición y llama al Use Case → 5. El Service ejecuta la lógica de negocio → 6. El Adapter de persistencia guarda/lee datos en Oracle → 7. La respuesta DTO regresa al frontend.

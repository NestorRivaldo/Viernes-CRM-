⚡ Método Ultra Rápido: Lanzador Automático de 1 Clic

Hemos creado en la raíz del proyecto el script activar-sistema.bat. Al hacer doble clic en él en la nueva PC, verifica Docker, arranca Keycloak, inicia el Backend Spring Boot, instala paquetes si faltan y levanta el Frontend abriendo el navegador automáticamente.

activar-sistema.bat
📦 1. Prerrequisitos de Software en la Nueva Computadora

Antes de encender los servicios, asegúrate de que la nueva máquina tenga instalado lo siguiente:

1. Java 21 (JDK)

Requerido por Spring Boot 4 y Java 21 (Eclipse Temurin 21 o Oracle JDK 21).

java -version

2. Node.js 20 LTS o 22 LTS

Requerido por Angular CLI v22 para compilar y ejecutar el frontend.

node -v && npm -v

3. Docker Desktop

Necesario para ejecutar Keycloak 25 y su base de datos PostgreSQL interna en 1 comando.

docker --version

4. Oracle Database

Oracle Database 23c Free (o 21c/19c/XE) en el puerto 1521 con PDB FREEPDB1.

lsnrctl status
⚙️ 2. Códigos y Comandos Paso a Paso para la Activación Manual

Si deseas encender cada servicio individualmente en terminales separadas, sigue exactamente esta secuencia:

0
Preparar la Base de Datos Oracle (Usuario y Privilegios)
El backend se conecta con el usuario BOM_VENTAS y contraseña 123456 a la base de datos conectable FREEPDB1. Ejecuta este script una sola vez en SQL*Plus o SQL Developer conectado como SYS AS SYSDBA:
sqlplus sys/password@localhost:1521/FREEPDB1 as sysdba 
-- 1. Cambiar a la sesión de la PDB de desarrollo
ALTER SESSION SET CONTAINER = FREEPDB1;

-- 2. Crear el usuario de la aplicación si no existe
CREATE USER BOM_VENTAS IDENTIFIED BY 123456;

-- 3. Otorgar los privilegios necesarios para crear tablas y operar
GRANT CONNECT, RESOURCE, DBA TO BOM_VENTAS;
GRANT UNLIMITED TABLESPACE TO BOM_VENTAS;

-- Listo: Spring Boot creará o actualizará todas las tablas (CRM_CLIENTES, CRM_PROPUESTAS, etc.)
-- automáticamente gracias a hibernate.ddl-auto: update
¿No tienes Oracle instalado en Windows? Puedes levantarlo instantáneamente con Docker con este comando:
docker run -d --name oracle23c -p 1521:1521 -e ORACLE_PASSWORD=123456 container-registry.oracle.com/database/free:latest
1
Levantar Keycloak 25 (OAuth2 / OIDC) en Docker
Abre una terminal en la raíz del proyecto (e:\LPII\Viernes) y arranca el contenedor con importación automática del Realm y sus usuarios:
Terminal CMD / PowerShell (Raíz del Proyecto) 
docker compose -f compose-keycloak.yml up -d
Verifica que esté listo abriendo en tu navegador:
  • Consola de Keycloak: http://localhost:8180 (Admin: admin / admin)
  • Metadatos OIDC del Realm: http://localhost:8180/realms/viernes-realm/.well-known/openid-configuration
2
Iniciar el Backend Spring Boot (Java 21)
Abre una segunda terminal, entra a la carpeta viernes-backend y arranca con Maven Wrapper. Los perfiles dev,keycloak ya están configurados por defecto:
Terminal CMD / PowerShell (viernes-backend) 
cd viernes-backend
.\mvnw.cmd spring-boot:run
Cuando veas Started ViernesBackendApplication in X.XXX seconds, comprueba la API:
  • Documentación Swagger UI: http://localhost:8080/swagger-ui.html
  • Health Check Actuator: http://localhost:8080/actuator/health (Debe retornar "status": "UP")
3
Iniciar el Frontend Angular (Node.js)
Abre una tercera terminal, ingresa a la carpeta viernes-frontend, instala dependencias (solo la primera vez) y ejecuta el servidor de desarrollo:
Terminal CMD / PowerShell (viernes-frontend) 
cd viernes-frontend
cmd /c "npm install"
cmd /c "npm start"
Abre tu navegador en:
http://localhost:4200
🛡️ 3. ¿Por qué NO va a haber problemas esta vez? (Solución de Fallos Previos)

La última vez experimentaste un fallo durante la configuración. A continuación te explicamos exactamente qué originó cada tropiezo anterior y cómo ha quedado blindado de forma permanente:

Causa del Fallo Anterior ¿Por qué Ocurría? Solución Definitiva Implementada Estado Actual
Error CORS en Keycloak (403 / Preflight) El frontend Angular enviaba cabeceras personalizadas de rastreo (X-Trace-Id) al endpoint de token de Keycloak, y Keycloak las rechazaba por política de seguridad estricta. Se actualizaron trace-id-interceptor.ts y jwt.interceptor.ts para excluir automáticamente las peticiones de Keycloak de cabeceras custom, y se configuró webOrigins: ["*"] en el Realm. ✓ RESUELTO Y PROBADO
Script Execution Policy en Windows (PowerShell) En Windows recién instalado, PowerShell viene con Restricted y bloquea archivos .ps1 como npm.ps1 o comandos directos de node. Los scripts y el lanzador automático activar-sistema.bat invocan cmd.exe /c directamente, eludiendo por completo las restricciones de PowerShell sin requerir permisos de administrador. ✓ BLINDADO
Colisión de Puertos (8080) Keycloak por defecto intentaba escuchar en el puerto 8080, chocando con Spring Boot. El archivo compose-keycloak.yml mapea el puerto de Keycloak a 8180 ("8180:8080"), dejando el 8080 100% libre para el backend Spring Boot. ✓ CERO COLISIONES
Colisión de Base de Datos Postgres (5432) Si la nueva PC ya tenía un PostgreSQL local en 5432, el contenedor de Keycloak fallaba al arrancar. Se configuró el puerto externo de PostgreSQL de Keycloak en 5433 ("5433:5432"), garantizando que nunca colisione con instalaciones locales previas. ✓ AISLADO
Usuario sin Roles o Login Confuso Se requerían múltiples credenciales o el modo demo se cruzaba con tokens reales. Se eliminó por completo el código mock/demo y se configuró en Keycloak un Usuario Maestro Único con todos los roles (`ADMIN`, `JEFE`, `VENDEDOR`), garantizando acceso pleno e instantáneo con una sola clave. ✓ ACCESO TOTAL
Fuga de Conexiones de Base de Datos El modo Open-In-View mantenía transacciones abiertas durante la serialización JSON. Se fijó spring.jpa.open-in-view: false y se auditaron todos los servicios con @Transactional(readOnly = true), garantizando cierre atómico y liberación inmediata en HikariCP. ✓ CONEXIONES SEGURAS

🔍 5. Comandos de Diagnóstico Rápido (Chequeo de Salud)

Si en la otra máquina deseas verificar que cada componente esté respondiendo correctamente:

Comandos de Verificación en CMD / PowerShell 
:: 1. Verificar si Keycloak responde:
curl -I http://localhost:8180/realms/viernes-realm/.well-known/openid-configuration

:: 2. Verificar si el Backend Spring Boot responde:
curl http://localhost:8080/actuator/health

:: 3. Verificar si el contenedor Docker está corriendo:
docker ps --filter "name=viernes-keycloak"

:: 4. Si alguna vez necesitas reiniciar Keycloak desde cero (limpiar volumen):
docker compose -f compose-keycloak.yml down -v
docker compose -f compose-keycloak.yml up -d
